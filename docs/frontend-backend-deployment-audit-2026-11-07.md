7 November 2026, before the scheduled midnight IST launch. The local production build examined was `DAkajcKQqz1GzT7vS8Pwl`. The public domain was serving Amplify production job 57, revision `1b0fcd4`, deployed 5 November.

**Decision. The current frontend is ready for stakeholder review. Hold release sign-off for the inquiry workflow and the repeatability of the release checks.** The November 5 version already has the same automatic public-opening time as the local candidate. ## Performance and operating risks

- **First useful frame.** Earlier same-session local measurements put cold factory readiness at about 2.5 seconds and the cold Leadership projection at about 5.9 seconds, with much faster repeat visits. These software-rendered browser timings identify where to profile. They cannot establish performance on a handset. Measure poster visibility, first meaningful live frame, scroll input and restoration after backgrounding on physical iOS Safari and Android Chrome. Retain native-resolution artwork while measuring setup work.
- **Artwork freshness.** The host and Next configuration assign a year of immutable caching to everything under `/optimized/`. The Leadership renderer loads a stable filename there. A replacement at the same URL can leave returning visitors with older art. Fingerprint changing files or restrict the immutable rule to versioned names. The candidate public directory contains roughly 226 MiB of tracked and Git-visible candidate assets. This is a packaging figure, not a page download.
- **Duplicate submissions.** A visitor can retry after the 20-second client timeout while the first request has already persisted. Each post receives a fresh UUID. Give the browser submission an idempotency key, keep that key through retries, and test that one inquiry produces one receipt and one notification.
- **Configuration and limits.** A missing table name selects the local file adapter. A missing sender skips email. The deployment recipe tolerates missing configuration. Validate required settings at release time and restrict the file adapter to explicit local development. Login and inquiry rate limits use per-process memory. Move production limits to a shared enforcement point if they are expected to apply across instances.
- **Navigation after launch.** Middleware redirects unknown public paths to Home. A visitor following a broken or retired link gets no explanation. Keep deliberate aliases and provide a useful 404 with a route back for other unknown paths.

## Sign-off sequence

1. Repair the production inquiry contract and notification path. Verify a controlled submission from the rendered form through persistence and mailbox receipt.
2. Update the obsolete checks and run both sides of launch against an isolated candidate. Check form availability, canonical links, old route aliases, robots and sitemap, including the transition at midnight IST on 8 November.
3. Freeze the candidate, build from a clean checkout, and repeat the route, asset and dependency gates. Review first-entry factory and projection behavior on a physical phone. Give tablet framing changes their own visual review.
4. Match the resulting deployment receipt to the release revision. Recheck the public entry, one lower-page deep link, artwork delivery and the first monitored inquiry once the public gate opens.
